# Domain documentation

This repository has one domain context.

Read `CONTEXT.md` before naming application concepts in code, tests, issues, or
documentation. Read ADRs under `docs/adr/` when they concern the area being
changed. Repository-wide decisions belong in that directory.

Use the terms in `CONTEXT.md` consistently. If the code needs a concept that
the glossary does not cover, check the C reference before introducing a new
name.

Call out any proposed change that contradicts an ADR. Do not silently replace a
recorded decision.
